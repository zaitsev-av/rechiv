# Rechiv Desktop

[English](README.md) · **Русский**

Локальный компонент Rechiv для macOS и Linux на Go. Он принимает аудиочанки от
Chrome-расширения, хранит состояние сессий, управляет очередью и держит один
Python/GigaAM worker в памяти.

## Запуск для разработки

Требования:

- macOS Apple Silicon или Linux amd64/arm64
- Go 1.27.0 (`asdf install` в корне репозитория)
- Python 3.10–3.13 с зависимостями из `service/`
- ffmpeg

Из корня проекта:

```bash
task setup
task run
```

Остальные команды доступны через `task --list`. Например, `task desktop:test`,
`task desktop:test:race`, `task desktop:build` и `task dev`. Для принудительного
выбора ускорителя можно использовать `task run DEVICE=mps` на macOS или
`task run DEVICE=cuda` на Linux.

По умолчанию данные сохраняются в:

```text
macOS: ~/Library/Application Support/Rechiv
Linux: ~/.rechiv
```

Сборка Linux amd64:

```bash
task desktop:build:linux
```

Сборка Linux ARM64:

```bash
task desktop:build:linux LINUX_ARCH=arm64
```

Исходник иконки приложения находится в `desktop/assets/icon.svg`. PNG для Linux
и полный macOS iconset можно пересобрать из корня репозитория:

```bash
task desktop:icons:macos
```

API слушает только `127.0.0.1:9876`. Все методы, кроме `/health` и bootstrap
`/auth/token`, защищены уникальным Bearer-токеном установки.

Расширение получает этот токен автоматически. Для ручной диагностики его можно
вывести командой `task desktop:token` и передать в заголовке
`Authorization: Bearer <token>`. Это не токен внешнего LLM.

Очередь распознавания последовательная, поэтому при отставании воркер берёт
самый свежий фрагмент записи: live-панель нужна для текущего разговора, а хвост
всё равно будет обработан до финализации. Пока очередь короткая — строгий FIFO.

Python-движок дополнительно режет полученный WAV по паузам и распознаёт каждый
речевой интервал отдельно. Это даёт настоящие таймкоды вместо одной метки на
весь фрагмент, а тишина до модели не доходит вовсе.

При старте приложение проверяет worker командой `ping` и логирует выбранные
интерпретатор и `worker.py`. Результат доступен в `GET /health` в поле `engine`
(`starting`, `ready`, `error`). Без этой проверки поломка Python-окружения
проявилась бы только на первом распознавании — через десятки секунд записи.

Интерпретатор по умолчанию берётся из `service/.venv`: он ищется рядом с
бинарником и выше по дереву проекта, и только потом — в `PATH`. Переопределяется
флагом `-python`.

Распознавание последовательное, поэтому очередь ограничена. Если она
переполнена, `POST /sessions/{id}/chunks` отвечает `503` с заголовком
`Retry-After`: фрагмент не принят и не потерян, расширение повторит загрузку.

Во время записи каждый готовый аудиофрагмент сразу попадает в общий
live-транскрипт. Расширение опрашивает `GET /sessions/{id}/live` раз в две секунды;
ответ содержит распознанные сегменты, статус сессии и прогресс по фрагментам.
После завершения тот же экран автоматически переключается на финальный
`result.json`, где уже доступны редактирование и саммари.

## Граница Go/Python

Go отвечает за жизненный цикл приложения, HTTP API, безопасность, сессии, очередь,
прогресс, восстановление и финализацию. Python worker получает путь к WAV-файлу и
возвращает сегменты распознавания через JSON Lines в stdin/stdout.
